# scipy is used for exactly one thing: `scipy.sparse.csgraph.dijkstra`, for the
# least-cost-path ventilation corridors in Stage 5 of
# docs/HEAT_AND_WIND_PROGRESS.md. A corridor is the cheapest through-route across
# a cost surface, and a hand-rolled priority queue in numpy would be slower and
# less trustworthy than the reference implementation. Nothing else in the project
# imports scipy, so this is a narrow, replaceable dependency rather than a
# numerical stack.
#
# PINNED BELOW 1.14 on purpose. SciPy 1.14 added `scipy.sparse.linalg._propack`,
# a compiled extension whose macOS wheel is rejected by this host's dyld:
#   ImportError: dlopen(.../_spropack.cpython-310-darwin.so): section
#   '__DATA/__thread_bss' has a zero-fill section type, but offset field is not
#   zero
# `scipy.sparse.__init__` imports `scipy.sparse.linalg`, which imports the broken
# extension, so the ENTIRE `scipy.sparse` namespace -- including the csgraph
# Dijkstra the corridors need -- becomes unimportable on 1.15.3. A
# `--force-reinstall` of the identical wheel does not fix it (same broken
# section). 1.13.1 predates `_propack` and imports cleanly. The alternative -- a
# hand-rolled Dijkstra fallback -- would be a second shortest-path implementation,
# which is the exact duplication this project forbids, so the pin is the fix.
scipy>=1.11,<1.14
